# Plan: load RIOT analysis state from a `.phdf` file

## Goal and command-line contract

Support

```sh
riot -a dump.phdf -i analysis.in
```

as an analysis-only start in which RIOT:

1. builds the mesh described by `dump.phdf`;
2. constructs packages and registered fields from `analysis.in`;
3. loads every compatible registered field present in the dump, independent of its `Independent`, `Restart`, or `FillGhost` metadata; and
4. fills ghost zones for every loaded field before `UserWorkBeforeLoop` and analysis outputs run.

The driver must not enter the evolution loop. Existing invocations retain their current meaning: `-i` starts a new problem, `-r` performs a restart, and `-a` on a restart file uses the existing analysis-restart behavior. A `.phdf` analysis load requires `-i`, because ordinary dumps need not contain a complete archived input deck.

## Implementation

### 1. Introduce an explicit analysis-load policy in Parthenon

In argument parsing/`ParthenonManager`, distinguish the existing restart policy from a new `analysis_data` policy when `-a` names an HDF5 data dump. Do not infer this merely from the filename suffix: inspect the HDF5 metadata that identifies the output type, with the suffix used only for a clear early diagnostic if necessary.

Keep the existing initialization order—parse `analysis.in`, initialize RIOT packages, and construct the mesh from the file—but pass the load policy into the HDF5 reader and package-loading path. Require an input file for `analysis_data`; leave restart input merging unchanged.

### 2. Generalize field loading without changing restart selection

Refactor the current restart-package loader into shared mechanics plus a selection policy:

- `restart`: retain the current `Independent || Restart` selection and all existing validation.
- `analysis_data`: enumerate field datasets in the file and load the intersection with fields registered by the packages created from `analysis.in`, regardless of field metadata.

For each selected field, validate centering, component dimensions, scalar type/precision conversion, block dimensions, and sparse identity before reading. Recreate sparse allocation from `SparseInfo` before copying data. Read interior data into the base `MeshData`; even when the file contains output ghost zones, regenerate ghosts to make the result independent of the writer's rank layout and stale neighboring values.

Fail with an actionable error for a same-named but incompatible registered field. Warn once on rank 0 for datasets that have no registered RIOT field, and for registered fields absent from the dump; do not dynamically invent fields because the input/package metadata supplies their semantics. Initially support every field topology already supported symmetrically by the HDF5 writer and reader; explicitly reject unsupported topologies rather than silently skipping them.

### 3. Add a one-time, explicit-field ghost exchange

Extend Parthenon's boundary-exchange API to accept an explicit list of loaded field UIDs (or an equivalent selector) that overrides only the usual `FillGhost` filtering for that call. The override must:

- allocate/use boundary buffers for the selected dense and allocated sparse fields;
- perform same-level exchange and AMR prolongation/restriction as applicable;
- apply the configured physical boundary conditions; and
- leave each field's persistent metadata unchanged.

After loading all interiors, run this exchange to completion across the base mesh before any RIOT analysis callback. Do not call RIOT's derived-fill hooks during this step: fields read from the dump, including derived fields, are authoritative and must not be recomputed or overwritten.

Document the boundary rule: internal and coarse/fine ghosts are always regenerated; physical ghosts use the boundary conditions in `analysis.in`. A user boundary callback must therefore handle any analysis-loaded field for which it requests physical ghost values.

### 4. Wire RIOT to the generalized path

RIOT's main program should continue to use Parthenon's normal `-a` control flow. Add only the RIOT-side callback or small driver hook needed to request the post-load explicit-field exchange, if this cannot live entirely in `ParthenonManager`. Record the loaded UID set during the read so RIOT does not guess from metadata afterward.

Ensure the sequence is:

```text
parse input -> initialize packages -> build file mesh -> allocate sparse fields
-> load field interiors -> fill ghosts for loaded UIDs
-> UserWorkBeforeLoop -> analysis_output blocks -> exit
```

### 5. Compatibility and diagnostics

- Make the new behavior conditional on `-a` plus a data-output file; add no new required input parameters.
- Do not change restart output contents, restart field selection, normal `FillGhost` selection, problem generation, or time evolution.
- Take time/cycle and mesh topology from the dump for analysis output metadata; take package configuration, boundary conditions, and requested analysis outputs from `analysis.in`.
- Validate coordinate system, dimensionality, block shape, and ghost width early. Report file and input values in mismatch errors.
- Print a concise rank-0 summary listing loaded, missing, ignored, and ghost-filled fields.

## Tests and acceptance criteria

Add a regression fixture that writes a multiblock `.phdf` containing: an independent `FillGhost` field, a derived field without `FillGhost`, a `Restart`-only field, and an allocated/deallocated sparse field. Analyze it with a separate input file and verify:

- all compatible file fields have exact interior values;
- all loaded fields have correct same-level, periodic/physical, and AMR coarse/fine ghost values;
- sparse allocation matches the file;
- `UserWorkBeforeLoop` observes the completed ghost fill;
- analysis outputs preserve the dump's time/cycle; and
- loading works with a different MPI rank count from the writer.

Retain regression coverage for ordinary `-i`, `-r`, and `-a` on restart files. Add negative tests for missing `-i`, incompatible field shapes, incompatible mesh geometry, and unsupported field topology. The feature is complete when these tests pass without any metadata changes to the fields used by a normal RIOT evolution run.

## Follow-up: coarse/fine ghost filling for explicitly loaded fields

Date: 2026-09-20

### Parameter input behavior

For `-a dump.phdf -i analysis.in`, populate `ParameterInput` by first loading the input
deck archived in the PHDF file and then overlaying `analysis.in`. This preserves the
original mesh, static-refinement, package, and problem parameters while allowing the
analysis input to replace boundary conditions, package options, and output configuration.
Command-line parameters remain the final override layer.

### Problem

The explicit-field boundary override currently bypasses the normal `FillGhost` filter
when enumerating boundary buffers. It also allocates coarse storage for selected fields.
This is sufficient for same-level communication, but it does not make fields without the
usual communication metadata participate in AMR restriction or prolongation.

AMR operations are registered in `ProResCache_t::RegisterRegionHost()` only when
`Variable::HasRefinementOps()` is true. `Metadata::HasRefinementOps()` currently derives
that decision from persistent flags such as `Independent`, `FillGhost`,
`ForceRemeshComm`, `GMGProlongate`, `GMGRestrict`, `Flux`, and `WithFluxes`. A derived
analysis-loaded field without those flags is therefore present in boundary-buffer loops
but absent from the refinement-operation subsets. Its same-level ghosts are filled while
its coarse/fine ghosts remain untouched.

A static two-level reproduction confirms the failure: an independent `FillGhost` field
has correct ghosts everywhere, while a loaded derived field without `FillGhost` has exact
interiors and correct same-level ghosts but zero ghost values on both sides of every
coarse/fine interface.

### Fix plan

1. Extend the analysis-data regression fixture to write and reload a static two-level AMR
   mesh. Include both an independent `FillGhost` field and a derived field without
   `FillGhost`, and verify fine-from-coarse prolongation and coarse-from-fine restriction.
2. Separate the decision that a field normally participates in refinement communication
   from the availability of refinement functions. Retain default or explicitly supplied
   refinement functions for mesh fields even when their persistent metadata does not
   normally select them for communication.
3. Pass the explicit boundary-communication override into refinement-cache registration.
   Under the override, register every supported selected and allocated field in the
   restriction/prolongation subsets. Without the override, retain the existing
   `HasRefinementOps()` selection exactly.
4. Preserve a field's configured custom refinement operators when present. For an
   explicitly communicated field without configured operators, use Parthenon's default
   restriction, shared prolongation, and internal prolongation operators. Ensure the
   default operator set has a valid cache/function identifier even if no normally
   communicated field in the resolved packages uses it.
5. Do not add or modify persistent metadata flags as part of the explicit exchange. The
   override and any fallback refinement-operator selection must remain local to that
   one-time communication call.
6. Reject loaded non-spatial or otherwise unsupported topologies before communication
   with an actionable field-specific diagnostic rather than silently skipping their AMR
   ghosts or applying an invalid default operation.
7. Verify that field interiors remain bitwise unchanged, sparse allocation remains
   consistent with the dump, physical and same-level ghost behavior is unchanged, and
   ordinary evolution and restart communication continue to use the existing metadata
   selection path.

### Acceptance criteria

- The derived field without `FillGhost` receives correct coarse/fine ghosts in both
  directions using the expected refinement operators.
- The independent `FillGhost` reference field continues to produce its existing result.
- The explicit analysis exchange does not change field metadata or invoke derived-fill
  callbacks after loading.
- The AMR analysis regression verifies exact interiors, same-level ghosts, physical or
  periodic ghosts, coarse/fine ghosts, and preserved dump time and cycle.
- Existing restart, non-AMR analysis, and normal evolution tests continue to pass.

## Follow-up: allocate only dump and analysis fields

Date: 2026-09-22

### Goal

Add a built-in `Metadata::Analysis` flag and use it to reduce the base state created by
the PHDF `-a` path. An analysis-data run must instantiate exactly the registered fields
whose names occur in the PHDF file, union the registered fields marked
`Metadata::Analysis`, minus an explicit user-provided list of PHDF fields to exclude.
Excluded fields must not be allocated or read, even if they are also marked
`Metadata::Analysis`. Registered state outside the resulting set must remain in the
resolved package metadata but must not be added to the base `MeshBlockData`. Ordinary
problem generation, restart, remeshing, and non-PHDF analysis behavior must remain
unchanged.

### Implementation plan

1. Add `Analysis` to `PARTHENON_INTERNAL_FOREACH_BUILTIN_FLAG` in
   `src/interface/metadata.hpp`, in the independent optional-flags section near
   `Restart`. Document it as an allocation request for the PHDF analysis-data path; it
   must not imply `Independent`, `Restart`, `FillGhost`, output selection, refinement
   communication, or persistence in a dump. The existing macro-generated declaration,
   definition, name lookup, printing, and flag-collection machinery should require no
   special-case code.

2. Add an optional ParameterInput vector for the PHDF deny list:

   ```text
   <parthenon/analysis>
   exclude_fields = field_a, field_b
   ```

   Read `exclude_fields` from the final merged input so values in the analysis input or
   command-line overrides take precedence over the deck archived in the PHDF file. The
   parameter is valid only for the ordinary-HDF5 `-a` analysis-data path and defaults to
   an empty list. Require every requested exclusion to name a dataset in the PHDF file;
   fail early with an actionable error listing absent names so spelling mistakes do not
   silently allocate and read an unintended field. De-duplicate repeated names while
   preserving deterministic diagnostics.

3. Compute the analysis allocation set in `ParthenonManager` after packages have been
   resolved, the HDF5 reader is available, and `exclude_fields` has been parsed, but
   before any `MeshBlock` constructs its base data container. Build a deterministic,
   de-duplicated vector containing:

   - every PHDF field name that is registered in `resolved_packages`; and
   - every registered field selected by `Metadata::Analysis`, whether or not it is in
     the file.

   Then subtract every name in `exclude_fields`. Exclusion is the final, highest-priority
   selection rule: a field named there must not be instantiated or read even if it is
   registered, present in the PHDF file, and marked `Metadata::Analysis`. Equivalently,
   the allocated set is
   `(registered PHDF fields union Metadata::Analysis fields) minus exclude_fields`.
   Continue to ignore file datasets that are not registered, because package metadata
   supplies topology, shape, sparse identity, and refinement operators. Preserve the
   current compatibility checks when a selected registered field is actually read.
   Keep separate sets for selected dump-backed fields, Analysis-only fields, and
   explicitly excluded file fields so loading and diagnostics do not infer provenance
   after allocation.

4. Thread an optional base-field selection through the restart-mesh construction path:
   `Mesh` restart constructor -> `BuildBlockList` -> `MeshBlock::Make` ->
   `MeshBlock::Initialize` -> `MeshBlockData::Initialize`. Represent “use the normal full
   state” separately from an explicitly empty analysis selection (for example with
   `std::optional<std::vector<std::string>>`), because the existing empty-vector API
   means “include every field.” All non-analysis callers must continue to use the full
   state without changing their call sites or behavior.

5. When constructing an analysis base container, add only the exact selected names and
   disable `MeshBlockData::Initialize`'s automatic `WithFluxes` expansion. A generated
   flux is itself a state variable and therefore must be present in the PHDF file or
   explicitly marked `Metadata::Analysis` to be allocated. Do not prune
   `resolved_packages`: package metadata queries and field validation must still know
   about every registered variable even though `HasVariable` is false for unselected
   base-state fields.

6. Make sparse handling obey the same exact-selection rule. Dump-backed sparse fields
   should be instantiated in the base container and have per-block backing allocation
   restored from `SparseInfo`. Avoid the normal allocation-controller expansion when it
   would allocate an unselected member of a sparse control group; add an analysis-only
   exact sparse-allocation helper if necessary, leaving the normal grouped
   `MeshBlock::AllocateSparse` behavior unchanged. For a sparse field selected only by
   `Metadata::Analysis`, allocate backing storage on every analysis block so the field
   is immediately available to the analysis pipeline. Do not silently add its
   controller, controlled siblings, or flux unless each independently satisfies the
   dump-or-Analysis selection rule and is not excluded. An excluded sparse field must not
   receive backing allocation from `SparseInfo`, including indirectly through allocation
   controller expansion.

7. Restrict `RestartPackages(..., analysis_data=true)` to the recorded, non-excluded
   dump-backed intersection rather than enumerating the now-reduced container and
   rediscovering the intersection. Load only those interiors, restore sparse allocation,
   and record only successfully loaded fields in `loaded_analysis_fields_`. Continue the
   explicit ghost exchange only for loaded non-flux fields; Analysis-only fields are
   allocated but not ghost-filled before the application computes or initializes them.

8. Update rank-0 diagnostics to distinguish the resulting categories: loaded from the
   dump, allocated because of `Metadata::Analysis`, explicitly excluded file fields,
   ignored file datasets with no registration, and registered fields omitted from the
   analysis state. Keep the existing loaded and ghost-filled summaries stable where
   practical so current test expectations and downstream log parsing remain useful.

9. Document `Metadata::Analysis` and `<parthenon/analysis>/exclude_fields` in the
   metadata/API documentation and in the PHDF analysis section of
   `doc/sphinx/src/outputs.rst`. State explicitly that the flag only controls allocation
   for `-a` on an ordinary HDF5 data output, does not cause a field to be written, and
   does not initialize or ghost-fill a field absent from the file. Document that
   `exclude_fields` overrides both PHDF presence and `Metadata::Analysis`, and affects
   allocation, reading, sparse restoration, and the explicit ghost exchange.

### Tests and acceptance criteria

1. Add metadata unit coverage confirming that `Analysis` is a built-in printable and
   queryable flag, composes with `FlagCollection`, and introduces no new validity
   constraint or implication for `Restart`, `Independent`, or `FillGhost`.
2. Extend the `analysis_data` regression package with four registered dense fields: one
   present only in the PHDF, one absent from the PHDF but marked `Analysis`, one both in
   the PHDF and marked `Analysis`, and one neither dumped nor marked. In the analysis
   callback, assert that the first three exist in base `MeshBlockData`, the fourth does
   not, the dump-backed interiors are exact, and the Analysis-only field can be safely
   initialized and consumed by the output pipeline.
3. Add exclusions covering a dump-only field and a field that is both in the dump and
   marked `Metadata::Analysis`. Assert that neither appears in base `MeshBlockData`, is
   read, or is included in the explicit ghost exchange. Also verify an empty deny list,
   duplicate entries, command-line override precedence, and an actionable failure for an
   exclusion that is absent from the PHDF file.
4. Add a `WithFluxes` case proving that selecting the parent does not implicitly allocate
   its generated flux, plus an independently selected flux case proving it is allocated
   when named in the dump or tagged `Analysis`, unless explicitly excluded.
5. Add sparse coverage for dump allocation/deallocation from `SparseInfo`, an
   Analysis-only sparse field allocated on every block, and a sparse control group in
   which unselected and explicitly excluded siblings remain absent.
6. Verify the existing same-level, physical/periodic, and AMR coarse/fine ghost checks
   still pass for every loaded non-flux field, and verify Analysis-only fields are not
   included in the pre-analysis explicit ghost exchange.
7. Run the focused metadata/unit tests and the `analysis_data` regression, then the
   existing restart and analysis regressions. The feature is complete when PHDF analysis
   allocates exactly
   `(registered(file fields) union Metadata::Analysis) minus exclude_fields`, reads no
   excluded dataset, normal runs still allocate the full registered state, and no
   persistent metadata is mutated at runtime.
