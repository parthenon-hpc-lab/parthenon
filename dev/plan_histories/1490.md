# Parthenon remeshing refactor: design and implementation plan

Target: user-supplied source archive, reported commit `c348b850a3daae118d8304b3de84d708ee1354a2`.
Prepared: 2026-11-12. Status: source inspection and implementation plan; no Parthenon implementation changes or runtime performance measurements have been made.

Archive SHA-256: `116f5ff5bb5d382fafb58c5aa1a7e6c12d84b8dc4fd0f7094f684f7da5025739`.

## Design preamble

Use the proposed order, with two additions: build an explicit old-to-new provenance map alongside the new topology, and finish with a distinct numerical finalization stage. Keep geometry, inventory, cost estimation, ownership, transfer scheduling, and execution in separate modules. They communicate through plain descriptors, rather than partially initialized `MeshBlock`s.

```cpp
// Tagging stays in the existing application/task workflow.
// Each old leaf exports AmrTag::{refine, same, derefine}.
// 'derefine' means permission; topology rules decide whether siblings may merge.
Refinement::Tag(md);                         // existing independent operation

// Called at a valid remesh boundary after advance/particle migration completes.
void Mesh::LoadBalancingAndAdaptiveMeshRefinement(...) {
  modified = false;
  UpdateExistingCostState();                 // retain current manual/default semantics
  if (!CollectivelyNeedsTopologyOrPlacementCheck()) return;

  auto old = CaptureOldMeshView(*this);      // immutable epoch, owners, state handles
  auto tags = CollectEffectiveTags(old);     // do not evaluate criteria a second time
  auto topology = PlanTopology(old, tags);   // nesting, sibling merges, stable provenance
  if (!topology.changed && !PlacementCheckDue()) return;

  auto inventory = PlanInventory(old, topology, schema, planning_hooks);
  // Inventory includes per-(variable,sparse-id) allocation/layout and exact
  // future-block particle counts. No destination MeshBlock exists here.

  auto costs = EstimateCosts(old, topology, inventory, selected_cost_policy);
  auto footprints = SizeResidentStorage(topology, inventory);
  auto ownership = PlaceBlocks(topology, costs, footprints, rank_budgets);
  auto transfers = PlanTransfers(old, topology, inventory, ownership);
  auto execution = ScheduleWithinMemoryBudget(old, footprints, transfers, ownership);
  ValidateCollectively(topology, inventory, ownership, execution);
  if (topology.is_identity && ownership.is_identity) {
    FinishNoOpDecision();                    // consume scheduled check as baseline does
    return;
  }

  auto next = ConstructDestinations(execution, inventory); // allocated as waves permit
  ExecuteTransfers(old, next, execution);                 // local copies or peer batches
  PublishMeshTopologyAndBlocks(next, topology, ownership);
  FinalizeRemesh(next, execution.refinement_state);        // shared/internal, BCs, ghosts
  CompleteAndReleaseOldResources(old, execution);          // GPU AND MPI completion
  ResetExistingLoadBalanceCounters();
  modified = true;
}
```

These are proposed APIs, not APIs already present. `ConstructDestinations` and `ExecuteTransfers` can interleave in bounded waves; the pseudocode describes their dependency, not an instruction to allocate every destination at once. `FinalizeRemesh` includes the refinement ordering below, so “transfer complete” does not imply the new mesh is ready for evolution.

For an unambiguous initial implementation, `ExecuteTransfers` fills copied/restricted target state and C2F coarse buffers; `FinalizeRemesh` owns all shared/internal prolongation. Child coarse buffers and refinement descriptors persist to that finalization. Parent network caches can be released once all dependent child coarse buffers have been populated. An optional later optimization may run shared prolongation per execution wave, but must make that phase explicit and preserve the later shared-value correction/internal-prolongation dependency.

Transfer rules:

| Old → new relationship | Same rank | Different ranks |
|---|---|---|
| Unchanged leaf | Reuse the `MeshBlock` and its physical storage | Copy the required field state and explicit metadata; reconstruct ghosts afterward |
| One parent → children | Read parent views into child coarse footprints, then prolongate | Send coarse input; prolongate on receivers; share one parent/stencil payload among children on each destination rank |
| Children → one parent | Restrict on each child's source owner, then assemble its owned parent region | Restrict before sending; send only owned restricted contributions; assemble on the parent owner |
| Unallocated sparse contribution | Initialize the relevant region from its declared missing-value policy | No numerical payload; explicit manifest determines allocation and default initialization |
| Particles | Route active records to their future leaves; retained leaves keep storage | Coalesce typed records by peer; route by destination leaf, preserving IDs and values |

Recommended first implementation: inherit the current SFC ordering/contiguous ownership contract, use existing registered refinement operators, and extract reusable pooled/coalesced transport below the halo-specific routing API. Build the contracts and tests before replacing communication.

### 1.2 The current `RedistributeAndRefineMeshBlocks`

The function occupies `src/mesh/mesh-amr_loadbalance.cpp:649–1010`. Its sequence is:

1. Clear `mesh_data` immediately.
2. Enumerate the changed forest, resolve new GIDs, build `newtoold`/`oldtonew`, and derive new costs from old blocks.
3. Run `CalculateLoadBalance`, modifying `nslist` and `nblist` before transfer/construction.
4. Restrict fine sources into their `coarse_s` buffers in a batch; fence.
5. Issue one MPI send per source-variable/target relationship.
6. Reuse same-rank, same-level blocks; call `MeshBlock::Make` for other local targets.
7. Replace `block_list`, change GIDs/LIDs, and build leaf partitions while old field requests remain outstanding.
8. Repeatedly probe/receive field messages; perform shared prolongation afterward.
9. Remesh swarms, rebuild GMG lists, wait for sends, invoke user block initialization.
10. Reconcile non-cell-centered shared values under temporary ownership, perform internal prolongation, restore ordinary ownership, fill boundaries and derived fields, and reset load-balance state.

The numerical operations are useful; orchestration, storage, transport, and publication are intertwined.

## 2. Stage contracts and data types

Place new remesh orchestration under `src/mesh/remesh/`. Keep numerical kernels under `src/prolong_restrict/` and reusable communication under `src/bvals/comms/` or `src/utils/`.

Use a small number of concrete structures. Avoid a hierarchy of virtual per-cell/per-field strategy objects. Cost and application planning callbacks run on the host; registered numerical operations retain their existing dispatch.

```cpp
struct BlockKey { LogicalLocation loc; }; // includes tree, level, logical coordinates
struct EpochBlockId { uint64_t epoch; int64_t gid; };

enum class Relation { unchanged, refined_child, coarsened_parent };
struct SourceContribution {
  EpochBlockId source;
  BlockKey source_key;
  int source_rank;
  ChildOffsets child;                    // when applicable
};
struct PlannedLeaf {
  BlockKey key;
  int64_t new_gid;
  RegionSize geometry;
  Relation relation;
  std::vector<SourceContribution> sources;
};
struct TopologyPlan {
  CandidateForest topology;
  std::vector<PlannedLeaf> leaves;         // deterministic forest/SFC order
  SuccessorMap successors;                // old leaf -> all destination leaves
  AuxiliaryGridPlan gmg;
  bool changed;
};
```

`BlockKey` is identity within the forest; GIDs are epoch-specific ordering indices. Do not use the old GID as a persistent key or leave unqualified old/new integers mixed in helper signatures. A parent has many target children, and a coarsened target has many source children: keep those relationships explicitly instead of reconstructing them from differences between neighboring integers.

The old view's descriptors are immutable, but its resource-lease table must allow completed sources to retire. Keeping an unconditional owning vector of every old block until the end would prevent the early releases assumed by a bounded-memory schedule. Retire all relevant block/stage/GMG/cache aliases before counting an allocation as freed; retain plain provenance metadata afterward.

Inventory uses a canonical schema and per-block state:

```cpp
struct FieldSchema {
  VarID id;                               // actual base name and sparse ID
  Metadata metadata;                      // includes actual per-ID tensor shape
  ScalarType type;
  RefinementOperatorIds operators;
  AllocationGroup controller_group;
  RemeshDataPolicy policy;
};
struct PlannedField {
  FieldSchemaId field;
  bool allocated_after_transfer;
  bool reserved_for_finalization;
  StorageLayout layout;                   // data, coarse, physical alias groups
  CounterPolicy counters;
};
struct PlannedSwarm {
  SwarmSchemaId swarm;
  uint64_t active_count;
  uint64_t capacity;
};
struct BlockInventory {
  BlockKey key;
  std::vector<PlannedField> fields;
  std::vector<PlannedSwarm> swarms;
  ApplicationStorageDeclaration app;
};
struct MemoryFootprint {
  uint64_t host_owned, device_owned;
  uint64_t execution_stage_reserve, finalization_reserve;
  EstimateQuality quality;                // exact array request / bound / estimate
};
```

Schemas contain definitions once; block inventories store schema indices and allocation bits/counts. Keep detailed inventories local to old owners/planning coordinators and exchange them only where needed. The globally replicated topology and scalar costs/footprints may follow existing architecture initially; avoid replicating every particle route and every full `Metadata` object on every rank.

## 3. Independent tagging and topology planning

### 3.1 Preserve the existing tagging unit

Keep `Refinement::Tag` callable in drivers/tasks. Add a const `MeshRefinement::GetRefinementTag()` returning `AmrTag` so orchestration no longer reads a private integer. Convert the stored flag to `AmrTag` when safe; initialize it explicitly to `same`.

The exported tag is effective per-block intent after local history/level rules. `derefine` is permission, never a command to destroy a block. Complete sibling agreement and proper nesting remain topology decisions.

During extraction, preserve `SetRefinement`'s existing neighbor guard. Moving that guard entirely into topology planning can be a separately tested simplification. Never rerun `SetRefinement` during inventory or placement: it increments derefinement history.

### 3.2 Produce a candidate topology without allocating block data

Move flag collection and topology logic out of `UpdateMeshBlockTree` into `PlanTopology`. Gather compact `(old key, effective tag)` records; sort explicitly by logical identity. Group derefinement candidates by parent and check for the complete daughter set. Apply refinement first and permitted coarsening afterward using existing `Tree::Refine`/`Derefine` nesting rules.

Keep the active forest unchanged until the plan is accepted. A straightforward implementation is an explicit metadata-only `Forest::CloneForRemesh()` for topology-changing events. It must clone mutable leaf/internal-node GID maps and rewire all tree-neighbor pointers, including self and periodic neighbors, while preserving coordinate transformations, geometry, and boundary callbacks. An ordinary `Forest` copy is unsafe: its tree map holds shared pointers, and `Tree` connectivity includes pointers to trees. Add clone-isolation tests. Identity topology plans need no clone. Account for the clone's host-memory/time cost; an edit overlay can replace it later if measurements justify that complexity.

Resolve GIDs once per candidate forest. `Tree::InsertGid` shifts current GIDs into old slots, so repeated resolution is not a harmless lookup. Derive provenance primarily from exact logical matches and parent/daughter relationships in the old leaf lookup. Use `GetOldGid` only as a checked compatibility aid.

Assertions:

- Old/new leaves cover the same physical domain without gaps/overlaps.
- Each new leaf is unchanged, a direct child of one old leaf, or a parent of a complete old sibling family.
- Proper-nesting-induced refinement is included even when the triggering block was tagged `same` or `derefine`.
- Every source and destination relationship exists in both directions and is deterministic across ranks.
- The first implementation supports one AMR generation per event, matching the existing transfer machinery. Diagnose a larger level jump rather than silently applying one-level kernels to it.

Initial mesh refinement calls this same pipeline, but `Mesh::Initialize` may rerun the problem generator. Preserve that lifecycle, including its clearing of particles before regeneration.

## 4. Inventory future data before constructing blocks

### 4.1 Canonical field and swarm schemas

Build from resolved-package `AllFields`, `VarID`, sparse-pool metadata, and swarm definitions. Do not generate sparse labels by hand or use a sparse ID as an array offset. Different IDs in a pool can have different tensor shapes. Include actual automatically registered flux fields once; do not add another implicit copy because the parent field has `WithFluxes`.

Assign wire schema IDs by explicitly sorting `(base_name, sparse_id)`, swarm names, and typed particle-field/component names. `AllFields()` is an unordered map; do not derive cross-rank identities from iteration order, pointers, or an unverified rank-local UID. A canonical particle-field ordering must be used consistently by packing and unpacking and validated against live source schemas.

For a concrete distributed inventory algorithm, assign each future leaf a planning coordinator: the owner of its lowest-old-GID contributor. This rule needs only provenance, so it is available before placement. Source owners send compact allocation/counter/count records to that coordinator, which computes the target union, controller closure, capacity and layout declarations. Refined children ordinarily need no cross-rank inventory exchange because they have one parent source. Coarsened parents can require a metadata reduction across old sibling owners. No field values or particle records are sent to a coordinator merely to inventory them.

Each coordinator evaluates the chosen cost policy and publishes one scalar cost/footprint summary per target to the compatibility placement stage. After placement, it forwards detailed target inventory to the selected owner; sources retain their own contribution/routing records for transfer-plan construction. Use sparse peer exchanges or batched metadata messages and deterministic record ordering. Verify source/target manifest agreement collectively before payloads. Application cost hooks must consume the supplied descriptor summaries rather than assume every contributing source block is local.

Three different questions must have separate answers:

1. Will storage exist? Include dense fields, allocated sparse fields, stages, scratch, fluxes, coarse buffers, and particles.
2. Does its state survive remesh? Initially preserve the existing remesh selection: `Independent OR FillGhost OR ForceRemeshComm`, with current flux selection.
3. How does its state change under refinement/coarsening? Use registered numerical operators, a declared application remap, or a declared reset/recompute policy.

Do not turn every allocated scratch array into a migration payload. Conversely, `ForceRemeshComm` state cannot disappear because it is not `Independent`. For non-mesh-tied arrays and custom application state, require explicit AMR semantics when overlap copy/restriction has no defined physical meaning. Provide same-level whole-array copy where valid. Diagnose unsupported policies during planning, before destination construction or MPI payloads.

### 4.2 Make allocation layout reusable

`Metadata::GetArrayDims` currently takes a `MeshBlock` for mesh-tied fields. Extract a pure layout API taking ordinary/fine/coarse `IndexShape`s and relevant geometry. Have both `Variable` construction and planning call it. Reuse/consolidate `GetIndexShapes` and `CalcIndexShapes`; do not create a dummy block for sizing or maintain a second set of shape formulas.

Account for `Cell`, `Face`, `Edge`, `Node`, `Fine`, `CellMemAligned`, symmetry directions, tensor dimensions, and coarse-buffer requirements. Use checked 64-bit products of the actual allocation dimensions, including padded topology dimensions. Wire payload size and resident allocation size are different quantities.

### 4.3 Resolve sparse state as a whole

For each future field instance:

- Unchanged leaf: inherit allocation/counters from its source, subject to existing force-allocation behavior on newly materialized blocks.
- Refined child: inherit the parent's allocation; include construction-required forced fields.
- Coarsened parent: allocate if any contributing child is allocated, or forced allocation requires it.
- Apply controller/controlled-variable closure and stage coherence before computing bytes. Include fake-sparse/compile-time-disabled-sparse behavior.

Do not let receive order decide allocation. In particular, an absent contributor must never deallocate a parent after another child supplied data. Initialize missing spatial contributions explicitly. For standard fields, use their declared sparse/default-state semantics; do not assume every default is zero. If a custom operator does not preserve a constant missing value, its remesh policy must describe or evaluate the transformed default, including any required stencil support.

Preserve `dealloc_count` and derefinement history on unchanged migrations using integer metadata. For newly refined/coarsened blocks, characterize and retain the baseline initialization/reset policy in the first refactor. Changing counter inheritance is a separate numerical-behavior change with an explicit test.

### 4.4 Count and classify particles before placement

Extract destination classification from `BuildBlockSendPlan` in `src/mesh/swarm_amr_remesh.cpp`. Separate geometry-based routing from peer-rank grouping and packing:

```cpp
ParticleRoutes PlanParticleDestinations(old_swarm, old_leaf, topology) {
  for_each_active_particle_on_device(p) {
    // unchanged/coarsened leaves have one successor; refined leaves select a child
    target[p] = FindSuccessorUsingExistingMidpointConvention(p);
    ++histogram[target[p]];
  }
  return {target, compact_active_indices, histogram};
}
```

Reuse the routing result during transfer after ownership is known. Keep it device-resident; reduce/copy only compact counts needed for planning. Count all active records according to the current mask semantics. Preserve the current strict `coordinate > midpoint` convention, including equality and inactive dimensions. Do not divide the parent's particle count uniformly among children.

Capture the complete `Real`/`int`/`uint64_t` component schema, including default x/y/z and optional persistent IDs. Validate runtime `Swarm::Add`/`Remove` changes against the schema; either reconcile compatible schemas through explicit declarations or fail preflight with a useful error. Acquire schemas without `block_list.front()` so ranks with no blocks work.

Planned counts describe migration of existing particles. A callback that creates/removes particles during construction/finalization must declare that behavior and any capacity reservation separately.

### 4.5 Declare stage and application storage

Reused local blocks currently retain block stages; new blocks initially have only `base`. Record immediate post-remesh allocations and the declared stage storage needed for the next advance separately. Honor `OneCopy`, shallow containers, shared coarse buffers, and aliasing; count physical allocations once. Do not unexpectedly start migrating integrator scratch-stage values that are currently reconstructed.

Add host planning hooks, registered at application/package setup, conceptually:

```cpp
void DeclareRemeshRequirements(const PlannedBlockContext &, InventoryBuilder &);
CostEstimate EstimateRemeshBlockCost(const CostContext &);
```

The declaration hook sees immutable old/new descriptors, not live new blocks or MPI communicators. It may declare extra state, resources, and initialization/remap policies; it must not construct targets, allocate their numerical arrays, communicate privately, or change the source state. Keep declaration and cost hooks separate. Preserve existing construction hooks and validate their realized storage against declarations when hard budgets are requested.

## 5. Costs, memory, and ownership

### 5.1 Cost policy interface

Expose one host callback consuming `PlannedLeaf`, its inventory, and old overlapping cost observations. Support:

| Policy | Behavior |
|---|---|
| `inherit` | Unchanged: source cost. Refined child: parent's per-block cost. Coarsened parent: volume-weighted mean of child block costs; current equal-volume case is their arithmetic mean |
| `parthenon` | A deterministic framework function over cells, allocated components, particles, etc.; initially a documented heuristic |
| `application` | Downstream callback over the same descriptors; returns finite positive cost plus optional diagnostic breakdown |

The inherited policy intentionally preserves current fixed-zone-count semantics: every refined child has a full block's cells, so dividing parent compute cost by the child count is not the compatibility rule. Summing all child compute costs into a single coarsened block is also not the current rule. Particle-heavy applications can choose a policy that uses exact future particle counts instead.

Gather old costs before they are reset or replaced. Validate finite positive outputs and establish deterministic behavior across ranks. Keep cost units consistent within an event. The future learned model will implement this interface; no online learner, timing instrumentation, or new automatic-balancer enablement belongs in this refactor.

### 5.2 Memory footprint with explicit guarantees

Compute these categories separately:

| Category | Required accounting |
|---|---|
| Immediate resident | Unique data/coarse/stage allocations, block objects/coordinates, all swarm capacities and auxiliary arrays, declared application storage |
| Next-advance reserve | Stage copies, lazy particle sorting arrays and other declared execution resources |
| Finalization reserve | Possible sparse allocations during ghost/derived processing, new halo/coalesced pools, GMG storage |
| Transfer peak | Source allocations still live, new targets, send/receive chunks, parent-stencil caches, restricted workspaces, routing tables, host mirrors and transport metadata |
| Runtime overhead/headroom | Allocator alignment, runtime/driver state, unmodeled application overhead; reported separately from exact requested-array bytes |

`MeshBlock::ReportMemUsage()` is useful as a diagnostic, not an exact prospective footprint. Its code explicitly excludes some swarm communication buffers, and swarm logging does not consistently count tensor components and all auxiliary arrays. Use the same sizing routine that performs allocations; validate predictions against unique realized allocations and, where available, allocator instrumentation.

Particle capacity is not active count. Preserve existing capacity for reused blocks; size new pools using a shared deterministic reserve/growth calculation or a new planned-capacity constructor/reserve API. Count default pools even for zero active particles. Preserve integer particle values exactly in transport.

Do not optimize an empty swarm to zero capacity unless the growth routine explicitly handles growth from zero. The current doubling loop can otherwise fail to make progress. Validate minimum capacity or implement/test the new zero-capacity contract.

Ghost filling can allocate fields outside the overlap-derived sparse union. Therefore report both expected occupancy and a conservative reservation. A hard cap requires conservative neighbor/controller closure (all sparse fields as fallback), registered bounds for derived/application work, and pool reservations. If those declarations are incomplete, label the result an estimate and refuse to advertise a hard memory guarantee.

GMG is not an afterthought: `BuildGMGBlockLists` creates unique entities keyed by `(LogicalLocation, block_coarsenings)`, reuses some leaf pointers, and attributes parents through representative leaves. Extract a descriptor-only `PlanGMGHierarchy` and use that same enumeration for sizing and later construction. Charge auxiliary storage to its representative-owner leaf or model an explicit ownership dependency. Do not count aliased leaves once per GMG grid list.

Auxiliary GMG blocks currently use ordinary `MeshBlock::Make` with full resolved packages. Their footprint therefore includes dense/forced fields, coordinates, default swarm pools/bookkeeping, and application-construction storage, not merely solver arrays. They receive no migrated leaf-particle records. A future stripped GMG constructor is a separate optimization requiring its own semantics/tests.

### 5.3 Placement API and current ownership constraints

Return an explicit `OwnershipMap` with `owner(new_key)`, `local_id(new_key)`, per-rank leaf lists, and memory/cost totals. The first placement adapter should preserve the current index-contiguous SFC assignment and produce compatible `nslist`/`nblist`.

This restriction is material: `UpdateBlockList`, `FindMeshBlock`-style indexing, cost gathering, and existing remesh code assume rank-contiguous GIDs. A future arbitrary partitioner must first remove those assumptions throughout its consumers. The API may admit arbitrary maps, but the initial adapter must validate/reject unsupported noncontiguous maps rather than manufacture prefix offsets for them.

Use positive compute weights and optional host/device budget constraints. Retain the current assignment when topology is unchanged and the existing balance gate says no change is needed. With no budgets, retain legacy weighted placement for compatibility tests. With budgets, use a deterministic constrained SFC partition implementation; distinguish a proven infeasible input from failure of a heuristic to find a partition. Never silently exceed a budget or claim a heuristic found the optimum.

Placement needs final storage; execution needs a schedule-specific peak. After candidate placement, build the transfer schedule and check peak memory. If it fails, reduce chunk/cache sizes, change legal transfer ordering, or request another candidate placement. Reject collectively before destination allocation if no supported plan fits. The original mesh must still be usable after a planning rejection.

For unified-memory/CPU–GPU systems, resource budgets must describe actual shared physical pools. Do not add host and device aliases of the same allocation and charge them twice against one physical-memory limit.

For equal-size fixed blocks, the compatibility inherited costs reduce to existing behavior. For memory limits, even unchanged topology can require movement despite acceptable compute balance. Define the two triggers independently.

## 6. Transfer graph and reusable transport

### 6.1 Plan regions, then bind views

```cpp
struct TransferRegion {
  EpochBlockId source;
  BlockKey destination;
  FieldSchemaId field;
  RemeshOperation operation;              // copy / coarse-input / restricted-region
  TopologicalElement element;
  RegionIndexer source_indices, target_indices;
  OwnershipMask owned;
  uint64_t element_count;
};
struct PeerBatch {
  int source_rank, destination_rank;
  uint64_t remesh_epoch, batch_id;
  std::vector<WireRecord> records;        // fixed schema IDs, offsets/counts, metadata
  uint64_t payload_bytes;
};
```

Geometry planning already has useful code: `BlockInfo` and the field-like template interface of `CalcIndices` in `src/bvals/comms/calc_indices.hpp`. Use metadata/layout adapters for preconstruction planning and bind actual `ParArray` views only during execution. Add explicit region binders for `BndInfo`/`ProResInfo` rather than new handwritten prolongation/restriction kernels.

Remesh provenance lies within one tree's parent/child coordinates; halo reconciliation can cross transformed tree interfaces. Preserve existing logical transformations and ownership masks when reusing index helpers. `CommunicateOne` narrows halo exchange, not the persistent interior or prolongation stencil required for remesh.

### 6.2 Share lower layers with halo exchanges

Reuse these layers:

- `ProResCache_t` and `refinement::{Restrict,ProlongateShared,ProlongateInternal}` for registered operations and batching.
- `CommBuffer<T>` for resource ownership, message state, request completion, and available local-buffer behavior.
- Existing `ObjectPool`/`Mesh::pool_map` Real-buffer allocation infrastructure where suitable.
- A factored peer-batch packing/transport facility used by a halo adapter and a remesh adapter.

Current `CoalescedBuffer` stores Real arrays and resolves `BndId` through active `boundary_comm_map`; its tags derive from live sender partition IDs. Extract below that routing dependency. The halo adapter continues to translate existing `BndId`/partition channels; the remesh adapter supplies explicit source/target spans, schema IDs, and batch IDs. No fake neighbors, destination `MeshData`, or live target boundary map is needed during planning.

For the first transport conversion, pooled per-region buffers plus shared coalescing are acceptable. The optimized path packs source regions directly into peer payloads and unpacks directly into destination regions, eliminating per-variable intermediate copies. Establish a real halo consumer/test for any extracted generic layer so it does not become an unused abstraction beside duplicated remesh MPI.

Use a generic payload representation with safe adapters for Real fields and typed/byte particle records. `CommBuffer<T>` is templated but contains numeric buffer initialization assumptions; audit before instantiating it for bytes rather than assuming every byte type already works. Particle byte serialization already exists and may retain its per-swarm grouping initially. Preserve exact `int` and `uint64_t` bits; do not cast them through Real.

### 6.3 Protocol and scheduling rules

The inventory/plan exchange supplies exact counts. Exchange compact manifests only between actual contributor/target peers or their designated coordinators, then post matching receives before sends. Include empty contributors as metadata when they affect allocation; they need no field payload message. Do not use a message per block-variable just to discover absence.

The wire header must serialize fixed-width values explicitly: epoch, schema version/hash, field/swarm IDs, source/target keys or agreed epoch GIDs, operation, region identity, payload offsets/counts, allocation and integer counters. Do not transmit native pointer-bearing structures or assume arbitrary C++ struct layouts match. Validate schemas/counts and plan agreement before payload execution.

Use checked 64-bit byte arithmetic internally. Chunk at the minimum of transport count limits, configured payload cap, and memory budget. Current MPI calls commonly take `int`; either use large-count APIs when available or split safely below those limits. Isolate remesh traffic with a dedicated communicator/context or proven disjoint tag scheme; check `MPI_TAG_UB`. Never put unbounded GIDs into an unchecked shifted tag. An epoch tag can be reused only after the prior epoch is drained.

Default coalescing groups across blocks/variables per peer and memory-space/type class; split only for bounded sizes and dependencies. The goal is fewer payload messages without unbounded staging or loss of progress. Target `O(peer batches + chunks)` messages, not one message per variable per block. Avoid global payload all-to-all. Sparse metadata exchange may initially follow the existing replicated topology model; particle values and routing lists remain on source/target owners.

### 6.4 Complete transfer case handling

**Unchanged/local.** Reuse the original block, fields, swarm pools, and applicable stage/application objects. Do not serialize or create duplicate arrays. Update its IDs only at publication after old-ID consumers have finished.

**Unchanged/remote.** Initially support a compatibility whole-array pack. Then trim mesh-tied fields to required persistent interior/topological state and transfer allocation/counters explicitly. Rebuild ghosts afterward. A field marked `FillGhost` is still selected for migration; it is not necessarily safe to omit its interior as “derived.” Non-mesh arrays need their declared copy policy. Do not use halo threshold suppression on allocated state, even if every value is below the allocation threshold.

**Refinement/local.** Construct the planned child after placement, initialize its required allocation set once, and gather its coarse input from the parent source. Registered prolongation follows in the finalizer. Source ghosts must already satisfy the same validity assumptions as the baseline. Check the remesh boundary/preconditions; if a required source halo is not valid, complete the appropriate old-mesh preparation before packing.

**Refinement/remote or mixed.** Group by `(old parent, field, destination rank)`. For all children on a peer, form the union of coarse-input windows needed by their operations. Send one union or one parent snapshot per peer, whichever is cheaper after padding/descriptor overhead; never send a separate whole-parent copy per child by default. Local children consume parent views directly. Each remote parent-stencil cache is read-only until all dependent children have gathered their coarse inputs; retain it or resend a bounded fragment according to the schedule. Child coarse buffers remain live for registered shared/internal prolongation in finalization.

Existing custom refinement ops do not expose a general minimum-stencil contract. Initially retain the full child coarse-buffer footprint currently supplied, including its required ghosts. An optional future `DescribeRequiredCoarseInput` contract can permit tighter windows. Do not assume a one-cell stencil because a default limiter happens to use it. A full-parent-per-peer fallback is both simple and significantly less redundant than current per-child sends.

**Coarsening/local, remote, or mixed.** Restrict each allocated source field once on its source owner. Pack only its owned restricted parent contribution. Give each child contribution a separate staging span or unpack directly into disjoint target regions. Preserve existing shared-element trimming: lower-side children omit the shared right face/edge/node where required, so one deterministic contributor writes each target element. Never overwrite a coarse staging buffer still read by an unpack kernel. Once disjointness/lifetime is proven, replace per-child fences with a batched dependency.

An unallocated fine sibling supplies a declared default contribution, not an implicit instruction to leave uninitialized memory. Allocate/initialize the parent once from the complete manifest. Refined/coarsened forced/controller fields may be resident even when they have no source payload.

**Particles.** Group the precomputed destination-key/source-index routes by new owner after placement. Reuse stable leaves without packing; coalesce changed leaves per peer, optionally per swarm. Reserve destination capacity before insertion to avoid repeated pool doubling and pack-cache rebuilds. IDs and physical values survive; slot indices/masks/routing/sort caches are rebuilt according to current swarm semantics. Do not interpolate particle values. Retain the current active/removal policy unless explicitly changed and tested.

**Empty ranks and zero data.** They participate in required control collectives, may gain/lose leaves, and never dereference a prototype block or create unnecessary payloads. A swarm with zero active particles still has schema/capacity overhead. Non-MPI builds execute exactly the same planned operations through local kernels without MPI types leaking into the planner.

### 6.5 GPU and MPI lifetime

Quiesce old halo/swarm requests before destroying/rebuilding their maps, partitions, or pools. Keep old blocks, stage data, view-of-view owners, and transfer resources alive until every referencing GPU kernel and MPI request completes. MPI send completion alone does not prove a local device consumer is done; a completed packing kernel alone does not release an outstanding send buffer.

Retain required synchronization at device-to-MPI boundaries unless a supported stream-aware ordering primitive supplies the same guarantee. Start with batched fences per execution wave; refine to execution-space dependencies where the platform supports them. Do not delete fences by inspection or use `MPI_Barrier` as a substitute for GPU completion. The desired optimization is removing unnecessary per-contributor fences and self-MPI, not assuming asynchronous work is already complete.

For peak budgets, a bounded wave owns its exact send/receive/cache resources. It makes receive/progress capacity available before issuing dependent sends and releases sources only after their last field AND particle consumer. Avoid circular “free old data before receiving the data that permits freeing it” schedules. If mandatory source+target+minimum workspace cannot fit, report infeasibility before starting. Waves can reduce staging/cache peaks; they cannot universally eliminate the need for simultaneously live source and destination state.

## 7. Construction, publication, and numerical finalization

Extend block construction with a planned-allocation/capacity input. Use the same constructor/layout code for ordinary startup and remesh; preserve public `MeshBlock::Make` through a default overload. Do not construct a fully default-allocated block and immediately tear down its arrays to match inventory. Run existing application construction at its appropriate lifecycle point, after assignment; it must honor declared storage when budgets are enforced.

Bind new block geometry/is-leaf information to the candidate topology explicitly. `MeshBlock::Initialize` currently queries `pmy_mesh->forest`; add a descriptor-based initialization path or an explicit topology view so a new block does not accidentally query the old forest. Helpers during execution take `OldMeshView`/`NewMeshView` rather than reading a hybrid of old and new public `Mesh` lists.

Retained blocks may be held by both views. Do not mutate their GIDs/LIDs/neighbors until no old lookup depends on those values. Establish an internal publication boundary for `forest`, `block_list`, `loclist`, `ranklist`, `costlist`, `nslist`, `nblist`, counts, levels, partitions, and epoch. Callbacks exposed to the new mesh must see a consistent new view.

Preserve the following partial order from the baseline; expose it in `FinalizeRemesh`, rather than hiding it in a generic transfer-complete hook:

1. Fill C2F coarse inputs and finish restriction/copy contributions.
2. Run `refinement::ProlongateShared` on new refined blocks.
3. Complete planned particle installation and clear obsolete swarm caches.
4. Materialize the preplanned GMG hierarchy at the baseline lifecycle position.
5. Drain any remaining old sends before reconfiguring resources; batch-complete dependent device work.
6. Invoke `InitMeshBlockUserData` with the baseline call semantics, including retained blocks. Do not silently change it to run only on newly allocated objects.
7. Establish temporary ownership that favors already-existing fine blocks over newly refined blocks; build tags/boundary resources and reconcile communicating non-cell-centered shared elements.
8. Run `ProlongateInternal` after shared values are correct, under the same applicable conditions as the baseline.
9. Restore ordinary ownership and finalize neighbor/GMG/boundary state.
10. Call `PreCommFillDerived`, full `CommunicateBoundaries`, and `FillDerived`, then make base `MeshData` available.
11. Reset the existing load-balance variables; set `modified` based on actual topology/ownership work; preserve driver timestep reinitialization.

Set `modified=false` at entry, including every no-op return. Preserve the baseline distinction between consuming a scheduled balance check (`lb_flag_` can clear even without movement) and resetting `step_since_lb` after actual redistribution. Update `nbnew`/`nbdel` from accepted topology changes, including nesting-induced changes, rather than raw tag counts. Cover these scheduler details with tests so extraction does not cause repeated balance checks or stale timestep initialization.

Clearing `MeshData`, package subsets, swarm pack caches, GMG lists, and communication maps must respect aliases and in-flight references. Plan/validate first; clear/rebuild caches at the execution/finalization boundaries, not at the beginning of planning. Release old state as early as its dependencies allow; keep only what finalization still needs.

The staged candidate topology makes preflight errors recoverable without corrupting the active mesh. Do not promise rollback after MPI/device execution or arbitrary user callbacks fail; define that failure policy explicitly and fail consistently across ranks.

## 9. Implementation sequence and acceptance gates

Treat this as several reviewable PRs/checkpoints, not a single replacement of a thousand-line routine.

### Phase 0 — Characterize the baseline

Capture source-level selection, counter, callback, particle and shared-element semantics. Add focused deterministic tests for current cases; run existing suites before changes. Record message counts, payload bytes, GPU fences, allocation peaks, and total remesh time on representative problems. No learned balancer is added.

Exit: behavior matrix and the finalization partial order are executable tests; separate baseline defects are identified.

### Phase 1 — Extract plans and the legacy executor

Introduce typed tags, epoch-qualified views/provenance, and plain plans. Extract named construction/transfer/finalization helpers while preserving existing operations. Add candidate-forest planning and isolation tests. Let the legacy executor consume the plan so new topology/ownership do not depend on MPI receive loops.

Exit: equivalent output/ownership on compatibility cases; preflight planning does not clear caches, mutate the active forest, or allocate destination blocks.

### Phase 2 — Inventory and shared allocation sizing

Implement metadata-only layouts, all-field inventory, sparse/controller/force allocation closure, particle classification/counts, stage/app declarations, and GMG descriptor enumeration. Split expected bytes from reservations. Extend constructors/reservation paths to realize that inventory. Run planning in diagnostic mode if needed before changing the executor.

Exit: inventory agrees with physical target allocation requests, per-ID shapes and exact particle destination counts; no dummy target blocks are used for planning.

### Phase 3 — Cost/placement interfaces and preflight memory validation

Implement inherited/framework/application policy selection and compatibility SFC placement. Make memory constraints and peak execution validation explicit. Preserve default/manual scheduling; keep automatic timing mode unavailable. Check no-op, fewer-blocks-than-ranks, and planning-rejection paths.

Exit: deterministic mapping; legacy results without budgets; budget failures happen before constructing destinations; callbacks only receive descriptors at planning time.

### Phase 4 — Shared transport and exact migration

Factor peer-batch mechanics with an existing halo consumer and regression tests. Switch remesh to planned manifests, explicit counters, exact sparse payload policy, posted receives and pooled bounded buffers. Add local C2F/F2C paths. Initially use full conservative C2F inputs and compatibility same-level payloads to isolate transport changes.

Exit: field/particle state matches baseline numerical semantics with coalescing on/off and serial/MPI; no self-MPI for local remesh; no counter-in-ghost writes; byte/count/tag limits validated.

### Phase 5 — Volume and synchronization optimization

Deduplicate C2F parent data per destination rank, pack restricted owned regions for F2C, trim valid same-level interior payloads, pack directly into peer buffers, remove redundant particle repacking, and schedule bounded waves. Remove per-child F2C fences only after disjoint-buffer/lifetime tests prove safety. Keep conservative custom-op stencil fallback.

Exit: measured lower message/payload/staging overhead where predicted; no numerical or end-to-end remesh regression on representative cases. Compare the full-parent-per-peer fallback against tighter unions rather than presuming smaller windows always win.

### Phase 6 — Finish lifecycle cleanup and remove legacy duplication

Consolidate finalization/caches/GMG construction, document hooks and guarantees, remove old probe-based helpers only after new coverage passes. Audit the future load-balancer integration surface: it should require supplying costs and invoking placement, not editing data transfer.

Exit: the source of truth for topology, layout, classification and numerical operators is shared; all remaining legacy paths are intentional and documented.

## 11. Guidance for the implementing Codex agent

1. Start from the reported commit, read the actual functions listed above, and preserve unrelated downstream changes. The archive itself is not an independently verified Git checkout; confirm the base in the implementation environment.
2. Implement one phase at a time. Keep an executable reference path while extracting contracts; remove duplication only after meaningful tests pass.
3. Do not add learned costs or enable the currently disabled automatic timer mode in this refactor.
4. Do not infer semantics from misleading names such as `vars_cc_`. Read the metadata selection and preserve its coverage.
5. Reuse `AmrTag`; expose effective tags. Keep tagging/history independent from topology and placement.
6. Never plan by constructing temporary `MeshBlock`s or allocating destination arrays. Geometry, schema, source data reductions and routing/count workspace are permitted during planning.
7. Preserve exactly one source of truth for layouts, particle classification, capacity rules, region indices and numerical operator dispatch.
8. Do not shallow-copy a `Forest` and assume isolation. Rewire tree connectivity and test it.
9. Keep old and new IDs, owners, geometry and views explicit. Do not publish partial metadata to existing callbacks.
10. Inventory individual variables/IDs, resident scratch and complete typed particle records. Separate persistent payload from storage and reinitialization policy.
11. Treat memory declarations honestly: exact requested-array bytes, conservative reservations and unmodeled overhead are different. Do not claim a hard cap from `ReportMemUsage` or active-particle counts alone.
12. Preserve source allocation independently of halo thresholds. Do not lose small allocated values or use halo `CommunicateOne` to shrink remesh state.
13. Keep receiver C2F prolongation and sender F2C restriction. Deduplicate parent coarse inputs per peer; preserve custom-stencil fallback and topological ownership.
14. Keep integer counters in explicit metadata and particle integer types intact. Never overwrite source ghost entries to smuggle control data.
15. Reuse buffers only after both MPI and device consumers complete. Provide local paths even when compiled with MPI. Remove synchronization only with a proved dependency replacement.
16. Preserve shared-element synchronization before internal prolongation and the baseline callback/GMG/derived lifecycle. A single “prolongate everything” call is not equivalent.
17. Keep placement compatible with contiguous-GID assumptions until every affected consumer has an explicit-directory alternative. Do not silently expand partitioner scope.
18. Treat no-op, empty-rank, initial-refinement and source-retained cases as first-class paths. They must not depend on a prototype destination block.
19. Confirm suspicious baseline bugs with separate tests/commits; do not bury fixes in refactoring diffs or update regression golds merely to obtain a pass.
20. Report which CPU/MPI/GPU tests actually ran, which were unavailable, and measured performance separately from expected improvements.
