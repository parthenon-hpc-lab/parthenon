# Coalesced comms: multiple comm lanes + real partitions (targeted rewrite of PR 1473)

[This is the plan for a second attempt at PR 1473. A first version of the PR already
existed; this plan replaces it with a smaller, more targeted set of changes, which is why
it refers to "PR 1473" and its existing approach.]

## Context
Coalesced comms can't run with more than one comm lane (what `SetBoundBufferId` currently
calls an "id"). Multigrid uses 2 lanes for `gmg_restrict_*` (mesh.cpp:221,
mg_solver.hpp:467), so **MG + `do_coalesced_comms=true` aborts in the Mesh constructor**.
While fixing that we found two more problems:
- Coalesced comms identify a partition by `MeshData::partition`, an int that restarts at 0
  on each grid (`BuildBlockPartitions`, mesh.cpp:467), so GMG partitions collide.
- `CoalescedBuffersRank::PackAndSend` FAILs when a partition has no off-rank neighbors
  toward that rank. That's a legitimate case.

PR 1473 fixed all of these, but it also added a "bundle" abstraction and moved the
`MPI_Comm_dup` calls out of the constructor. The targeted version:
1. multiple lanes,
2. partitions taken from `BlockListPartition` rather than the int,
3. skip partitions with no off-rank neighbors,
4. rename id → comm lane.

**Why PR 1473 moved the comms:** `CoalescedComms` is built in Mesh's init list (mesh.cpp:101),
before `SetNumberOfCommChannels` runs (mesh.cpp:221). The lane count isn't known there, and
`MPI_Comm_dup` is collective, so comms can't be dup'd lazily. **This plan doesn't need that.**
It keeps one comm per sender BoundaryType, dup'd in the constructor as on develop, and puts
the lane in the MPI tags.

Work happens on `lroberts36/coalesced-comms-multi-id`, rebuilt from develop. Force-pushing
to PR 1473 is a separate step that needs the user's confirmation.

## Approach

### A. MeshData carries its partition (`src/interface/mesh_data.{hpp,cpp}`)
- Replace `int partition{-1};` with `std::shared_ptr<BlockListPartition> partition;`.
  `Initialize(part)` sets `partition = part;` and `Initialize(src)` copies it.
  `Initialize(BlockList_t, ...)` leaves it null.
- Lifetime: `mesh_data.clear()` runs at the start of a remesh, before the partitions are
  rebuilt (mesh-amr_loadbalance.cpp:653). So any live MeshData points at a current partition,
  and the shared_ptr rules out address reuse.

### B. Coalesced comms map partitions to per-rank tags (`src/bvals/comms/coalesced_buffers.{hpp,cpp}`)
- New member `std::map<const BlockListPartition *, int> partition_tags;` with
  `void RegisterPartition(const BlockListPartition *)`. It assigns the next integer if the
  partition is new. `clear()` empties it.
  - The tag only needs to be unique on the sending rank, because the receiver learns tags
    from the info message (`TryReceiveBufInfo`).
  - The rest of the code (`CoalescedBuffer::partition`, `coalesced_bufs` keys, `BndId`
    partition field, `2*p`/`2*p+1` tags) stays int-based and now holds this tag.
- `AddSendBuffer(const BlockListPartition *, ...)` looks up the tag. If the partition isn't
  registered, that's an error.
- A private helper resolves `pmd->partition.get()` to a tag. If it's null or unregistered,
  `PARTHENON_FAIL` with the existing "unregistered partition" message.
- **Fix 3:** `CoalescedBuffersRank::PackAndSend` / `IsAvailableForWrite` take the tag.
  If a rank has no buffer for that tag, `PackAndSend` is a no-op and `IsAvailableForWrite`
  returns true. That replaces the current FAIL.

### C. Lanes (same files + `bnd_id.{hpp,cpp}`, `build_boundary_buffers.cpp`)
- The buffer maps are keyed `std::tuple<int rank, BoundaryType, int lane>`.
  `CoalescedBuffersRank` and `CoalescedBuffer` get an `int lane` member.
- Top-level `IsAvailableForWrite` / `PackAndSend` / `TryReceiveAny` use
  `lane = pmd->GetCommLane(b_type)` and only visit entries with that `(b_type, lane)`.
- Tags. Comms stay one per sender btype (constructor unchanged).
  `nlanes = pmesh->GetNumberOfCommLanes(GetAssociatedSender(b_type))` (fixed once comms
  are built).
  - Data: `2*(nlanes*p + lane)`. Sparse status: that `+ 1`.
  - Info message: `lane` replaces `int(GetAssociatedSender(b_type))`, which was redundant
    with the per-btype comm.
  - Info and data tags can overlap on the same comm, as they already do on develop. That's
    safe because `ReceiveBufferInfo` blocks until all info has arrived before any data send.
- `BndId::GetSend(..., int lane)` passes the lane to `SendKey` and removes the TODO.
- `RegisterCoalescedCommsSubset<BTYPE>`:
  - Calls `RegisterPartition(md->partition.get())` once per MeshData, before the neighbor loop.
    That way every partition gets registered even if it has no off-rank neighbors.
  - Loops `lane < GetNumberOfCommLanes(BTYPE)` around Add{Send,Recv}Buffer, the same
    pattern as `BuildBoundaryBufferSubset`.
- Remove the `n_channels == 1` REQUIRE in `Mesh::SetNumberOfCommChannels` (mesh.hpp:~346).

### D. Rename id → comm lane
- `MeshData::SetCommLane` / `GetCommLane` (and `comm_lanes_` storage).
  `Mesh::SetNumberOfCommLanes` / `GetNumberOfCommLanes` / `LockCommLaneNumbers`.
  `SendKey`/`ReceiveKey`/`TagMap::GetTag`/`AddMeshDataToMap` parameters become `lane`.
  Update the call sites in mg_solver.hpp, mesh.cpp, bvals_utils.hpp, build_boundary_buffers.cpp,
  and tag_map.
- Keep `[[deprecated]]` inline aliases for the old public names (`SetBoundBufferId`,
  `GetBoundBufferId`, `SetNumberOfCommChannels`, `GetNumberOfCommChannels`), as PR 1473 did.
- Reuse what we can from the PR branch via `git show`, applied through Edit/Write only:
  the rename hunks, the CHANGELOG/doc text, and the coalesced `poisson_gmg` regression cases
  plus the `--num_steps 6` change. Drop the bundle/SetupComms/grid-id-map pieces.

## Deviations during implementation
- `CoalescedBuffersRank::PackAndSend` / `IsAvailableForWrite` kept develop's
  `MeshData<Real> *` signatures instead of taking the partition tag. They resolve the tag
  themselves via `pmesh->pcoalesced_comms->GetPartitionTag(pmd)`, so `GetPartitionTag` is
  public rather than a private helper.
