# OpenPMD Analysis-Load Parity Plan

## Goal

Make `RestartReaderOPMD` support the dump-analysis startup path implemented by the
HDF5 reader. An application invoked with `-a` on an openPMD dump should discover the
logical mesh fields stored in that dump, apply the same optional field filtering as
HDF5, reconstruct the analysis state, load field and sparse data through the existing
restart machinery, fill boundaries, and run analysis without changing ordinary
openPMD restart behavior.

## Phase 1: Define a backend-independent field catalog

- Keep `RestartReader::GetFieldNames(filter)` as the common analysis-facing API and fix
  the openPMD override to accept the same filter argument as the base and HDF5 readers.
- Build the catalog from logical Parthenon variable labels, not openPMD mesh-record
  names. A single variable may produce records for several AMR levels, topological
  elements, and components, so exposing record names would duplicate fields and fail
  for vectors, tensors, face/edge variables, and sparse IDs.
- Factor the small filter/intersection operation into shared reader-side logic, or
  otherwise keep the HDF5 and openPMD implementations behaviorally identical:
  - an empty filter returns every field in deterministic file order;
  - a nonempty filter returns only fields both requested and present;
  - missing requested fields are omitted here and handled by the existing analysis
    state-selection diagnostics rather than by backend-specific failures.

## Phase 2: Persist openPMD logical field names

- In `OpenPMDOutput::WriteOutputFileImpl`, derive the field-name vector from the same
  `all_vars_info` collection used to create mesh records and sparse metadata.
- Store that vector as an iteration attribute named consistently with the HDF5
  `OutputDatasetNames` attribute. Write full labels, including sparse IDs, exactly once
  and preserve the deterministic `all_vars_info` order.
- Write the attribute for ordinary data dumps as well as restart/core outputs so any
  complete openPMD dump accepted by `-a` is self-describing. Do not include particle
  species or internal record/component names in this mesh-field catalog.
- Keep the metadata addition backward-compatible: it augments the current openPMD
  format without changing mesh-record names or the data layout consumed by existing
  readers and tools.

## Phase 3: Read current and legacy openPMD files

- Implement `RestartReaderOPMD::GetFieldNamesImpl(filter)` in
  `src/outputs/restart_opmd.cpp` and leave only its declaration in the header.
- Prefer the new iteration-level field-name attribute when present.
- Provide a compatibility fallback for files written before the attribute was added:
  - for current format-version records, strip the trailing AMR-level and topological
    encoding from each mesh-record name, then deduplicate the resulting logical labels;
  - account for every supported topological marker (`CC`, `F1`-`F3`, `E1`-`E3`, and
    `NN`) and names containing underscores;
  - use `SparseFields` as an additional authoritative source for sparse labels;
  - preserve first-seen order and reject ambiguous legacy encodings with a clear error
    instead of silently selecting the wrong application field.
- Reuse or add narrowly scoped helpers beside
  `OpenPMDUtils::GetMeshRecordAndComponentNames` so writer and reader agree on the
  record-name grammar rather than maintaining unrelated string parsing rules.
- Confirm that discovery does not require loading record payloads and remains valid
  after the iteration is explicitly opened in serial and MPI configurations.

## Phase 4: Complete the analysis data path

- Exercise the existing `VariableExists`, `ReadBlocks`, `GetSparseInfo`, and
  `BlockdataIsPadded` paths with the discovered analysis descriptor and correct any
  assumptions that only hold for full restarts.
- Preserve openPMD's native unpadded/interior layout: use the existing chunk-offset and
  extent calculation for each block, level, topological element, and component, then
  rely on the analysis initialization path to populate destination ghost zones.
- Verify that filtered-out fields are neither allocated nor read, while selected dense
  and sparse fields retain their shapes, component ordering, allocation masks, and
  deallocation counts.
- Keep normal `-r` behavior unchanged, including package-parameter restoration, swarm
  loading, format-version handling, and mixed HDF5/openPMD restart sequences.

## Phase 5: Regression and unit coverage

- Extend the analysis-data regression with an openPMD producer/output variant and run
  the second step with `-a` on the generated `.bp` dump.
- Reuse the HDF5 analysis assertions to verify:
  - all file-backed registered fields are discovered when no filter is supplied;
  - an explicit field filter selects only its intersection with the dump;
  - dense, derived, vector/component, and sparse-ID labels map to one logical field;
  - excluded or omitted fields are not allocated or written by the analysis run;
  - interiors survive the load and same-level, physical, and coarse/fine ghosts are
    valid after analysis initialization;
  - time, cycle, input overrides, and analysis-only fields behave identically for HDF5
    and openPMD sources.
- Add focused reader tests for the new attribute, filtering, duplicate record removal,
  names containing underscores, multiple AMR levels/topological elements, and the
  legacy fallback. Include a negative test for a legacy name that cannot be decoded
  unambiguously.
- Retain the existing `restart_opmd` regression as the non-analysis compatibility gate.

## Validation

- Run `git diff --check` and the repository formatter on touched C++ files.
- Build with both HDF5 and openPMD enabled.
- Run focused reader/unit tests, the HDF5 and openPMD analysis-data regressions, and the
  existing `restart_opmd` regression in serial.
- Run the openPMD analysis and restart regressions with the configured MPI test size to
  verify collective iteration opening, metadata visibility, and block-local chunk
  reads.
- If supported by CI, also build with only one output backend enabled to ensure the
  shared `RestartReader` interface and conditional compilation remain correct.

## Scope Boundaries

- Do not redesign the analysis state-selection or boundary-fill algorithms; this work
  supplies openPMD with the same field-discovery and loading contract already used by
  HDF5.
- Do not change the openPMD mesh data layout, naming format, or restart semantics solely
  for analysis loading.
- Swarm discovery for analysis is outside this parity step unless the common analysis
  path begins selecting file-backed swarms; existing swarm restart support must remain
  intact.

# Follow-up Test Plan: HDF5 and Backend-Independent Analysis

## Goal

Add coverage for the preexisting HDF5 analysis path and the shared analysis-startup
behavior introduced earlier in this branch. Tests should distinguish reader-specific
metadata discovery from backend-independent state construction, mesh initialization,
parameter precedence, and analysis-only execution so failures identify the responsible
layer rather than appearing only as an end-to-end file mismatch.

## Phase 1: Register and complete the HDF5 analysis regression

- Finish the `tst/regression/test_suites/analysis_data` fixture and register it in
  `tst/regression/CMakeLists.txt` when HDF5 is enabled. Use two steps: produce a normal
  `.phdf` dump, then invoke the same executable with `-a <dump> -i <analysis input>`.
- Add the small application-side test fields and diagnostics needed by the fixture:
  file-backed dense and derived fields, a field excluded by the analysis filter, a
  field omitted because it is absent from the dump, and dense and sparse
  `Metadata::Analysis` fields initialized only during analysis.
- Verify the selected state explicitly: loaded, analysis-only, excluded, and omitted
  labels must be disjoint and match the expected sets. Confirm excluded and omitted
  fields are neither allocated nor emitted by the analysis output.
- Compare every loaded field's interior against the producer dump, including a derived
  field and a multi-component or non-cell-centered field, so the test exercises shape,
  component, and topology preservation rather than only scalar cell-centered data.
- Retain the draft AMR ghost checks for physical, same-level, coarse-to-fine, and
  fine-to-coarse boundaries. Run with different producer and analysis boundary
  conditions to prove that geometry comes from the dump while boundary behavior comes
  from the analysis input.
- Add sparse dump coverage with at least one allocated and one deallocated block and at
  least two sparse IDs. Verify the selected IDs, per-block allocation mask, deallocation
  counts, interior values, and post-load ghost values.

## Phase 2: Unit-test HDF5 field discovery

- Add focused `RestartReaderHDF5::GetFieldNames` tests beside the existing output-reader
  tests. Create minimal temporary HDF5 fixtures rather than running the full example.
- Cover the normal `OutputDatasetNames` path with deterministic file order, an empty
  filter, a partially matching filter, unknown requested names, names containing
  underscores, and full sparse labels such as `pool_7`.
- Cover the compatibility path for files without `OutputDatasetNames`: enumerate root
  datasets, ignore groups and bookkeeping datasets (`SparseInfo`,
  `SparseDeallocCount`, `VolumeLocations`, `Levels`, and `LogicalLocations`), and return
  only actual field datasets.
- Verify that filters behave identically for metadata-backed and compatibility catalogs:
  preserve catalog order, do not duplicate repeated requests, and do not fail merely
  because a requested field is absent.
- Keep these tests conditional on HDF5 and use scoped temporary paths with cleanup so
  unit-test execution does not leave `.phdf` artifacts in the source tree.

## Phase 3: Unit-test analysis state resolution

- Extend `tst/unit/test_state_descriptor.cpp` with direct tests of
  `ResolvePackagesAnalysis`, independent of either file format.
- Construct multiple packages containing dense, derived, sparse, vector/tensor,
  face/edge/node, and duplicate provided fields. Supply a synthetic available-field
  catalog and verify that only the intersection plus `Metadata::Analysis` entries is
  present in the resolved state.
- For file-backed fields, verify metadata transformation precisely: remove
  `Independent` and `WithFluxes`; add `Restart`, `FillGhost`, and `CommunicateOne`; and
  preserve type, topology, shape, vector/tensor flags, package association, and any
  other non-conflicting metadata.
- For sparse pools, verify that only available sparse IDs are registered, each ID keeps
  its individual shape and vector/tensor metadata, unavailable IDs are absent, and the
  pool receives the same restart/communication flag transformation as dense fields.
- Verify `Metadata::Analysis` dense fields are included when absent from the file and
  are added only once when packages overlap. Add corresponding coverage for an
  analysis-only swarm and all of its registered values.
- Add negative or diagnostic coverage for file labels that no package registers and for
  incompatible duplicate registrations, documenting whether the intended behavior is
  omission, warning, or failure.

## Phase 4: Test analysis startup and execution semantics

- Add argument-parser coverage showing that `-a` sets analysis mode without setting
  restart mode, stores the source filename, requires a separate `-i` input file, and is
  mutually well-defined with `-r`, missing arguments, and ordinary startup options.
- In the HDF5 regression, verify parameter precedence at all three layers: parameters
  embedded in the dump are loaded first, the analysis input overrides them, and command
  line assignments override both. Check representative package, time, cycle, mesh
  boundary, and output parameters.
- Verify source dispatch accepts analysis input from `.phdf`, `.rhdf`, and `.bp` when
  the relevant backend is enabled and emits a clear failure for unsupported extensions
  or disabled backends. Keep the behavioral assertions common while backend fixtures
  provide only file creation and data comparison.
- Instrument the example callbacks or output artifacts to prove that analysis startup
  does not run problem generation, does not execute the evolution loop, and does not
  call the normal pre-communication or post-communication derived fills before loaded
  data is exchanged.
- Verify boundary communication still occurs, the analysis output is written exactly
  once only for outputs marked `analysis_output = true`, ordinary/final outputs are not
  written, and attempting to use an analysis-produced file as a normal restart triggers
  the intended guard.
- Check that `ParthenonManager::IsAnalysis()`, `Globals::is_restart`, the driver output
  signal, and the final time/cycle reported to callbacks consistently distinguish
  analysis from restart.

## Phase 5: Protect normal restart and initialization behavior

- Run the same producer through ordinary `-r` and analysis `-a` paths and assert their
  intentional differences: restart restores the full resolved state and restart
  parameters, while analysis uses the filtered state and analysis input overrides.
- Retain existing HDF5 restart regressions as compatibility gates and add assertions
  that the new `MeshInitType` dispatch leaves problem-generation and restart callbacks,
  derived fills, and output cadence unchanged outside analysis mode.
- Exercise serial and MPI runs with multiple blocks per rank and ranks with no local
  source blocks where supported, ensuring collective file access and boundary setup do
  not depend on every rank owning data.

## Phase 6: Cover supporting swarm and pack changes

- Extend `tst/unit/test_swarm.cpp` for the lazy empty-index cache: add particles after
  growth, remove none/some/all particles, clear and refill the swarm, and verify active
  counts, maximum active index, reused slots, and zero-particle behavior.
- Test large batched insertion that requires multiple capacity doublings and the
  overflow guard without allocating an impractically large pool.
- Verify cached communication packs are reused when the schema is unchanged and
  invalidated after adding or removing `Real`, `int`, or `uint64_t` swarm values and
  after resizing the pool.
- Add an MPI swarm communication case with an empty sender and a nonempty neighbor to
  verify zero send sizes, followed by a case that removes particles during transport
  and confirms the reduction computes both the removal count and new maximum index.
- Add a narrow host/device construction test for default-constructed `PackIdx` and a
  multi-block `SwarmPack` lookup test around every flat-index boundary, including empty
  blocks, to protect the new offset storage and integer binary search.

## Validation Matrix

- Run unit tests in HDF5-only, openPMD-only, and combined builds so the shared abstract
  `RestartReader` contract and conditional compilation are exercised independently.
- Run the HDF5 `analysis_data` regression in serial and with the standard MPI test size;
  run the existing openPMD analysis regression with the same backend-independent
  assertions wherever practical.
- Run ordinary HDF5/openPMD restart, swarm communication, and swarm AMR/remesh tests to
  catch regressions outside analysis startup.
- Run formatting, Python syntax checks, `git diff --check`, and confirm all temporary
  test files are created under the test output directory and removed by the harness.
