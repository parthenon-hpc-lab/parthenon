# OpenPMD Analysis-Load Parity Plan

## Goal

Make `RestartReaderOPMD` support the dump-analysis startup path implemented by the
HDF5 reader. An application invoked with `-a` on an openPMD dump should discover the
logical mesh fields stored in that dump, apply the same optional field filtering as
HDF5, reconstruct the analysis state, load field and sparse data through the existing
restart machinery, fill boundaries, and run analysis without changing ordinary
openPMD restart behavior.

## Phase 1: Define a backend-independent field catalog

- Keep `RestartReader::GetFieldNames(filter)` as the common analysis-facing API and fix
  the openPMD override to accept the same filter argument as the base and HDF5 readers.
- Build the catalog from logical Parthenon variable labels, not openPMD mesh-record
  names. A single variable may produce records for several AMR levels, topological
  elements, and components, so exposing record names would duplicate fields and fail
  for vectors, tensors, face/edge variables, and sparse IDs.
- Factor the small filter/intersection operation into shared reader-side logic, or
  otherwise keep the HDF5 and openPMD implementations behaviorally identical:
  - an empty filter returns every field in deterministic file order;
  - a nonempty filter returns only fields both requested and present;
  - missing requested fields are omitted here and handled by the existing analysis
    state-selection diagnostics rather than by backend-specific failures.

## Phase 2: Persist openPMD logical field names

- In `OpenPMDOutput::WriteOutputFileImpl`, derive the field-name vector from the same
  `all_vars_info` collection used to create mesh records and sparse metadata.
- Store that vector as an iteration attribute named consistently with the HDF5
  `OutputDatasetNames` attribute. Write full labels, including sparse IDs, exactly once
  and preserve the deterministic `all_vars_info` order.
- Write the attribute for ordinary data dumps as well as restart/core outputs so any
  complete openPMD dump accepted by `-a` is self-describing. Do not include particle
  species or internal record/component names in this mesh-field catalog.
- Keep the metadata addition backward-compatible: it augments the current openPMD
  format without changing mesh-record names or the data layout consumed by existing
  readers and tools.

## Phase 3: Read current and legacy openPMD files

- Implement `RestartReaderOPMD::GetFieldNamesImpl(filter)` in
  `src/outputs/restart_opmd.cpp` and leave only its declaration in the header.
- Prefer the new iteration-level field-name attribute when present.
- Provide a compatibility fallback for files written before the attribute was added:
  - for current format-version records, strip the trailing AMR-level and topological
    encoding from each mesh-record name, then deduplicate the resulting logical labels;
  - account for every supported topological marker (`CC`, `F1`-`F3`, `E1`-`E3`, and
    `NN`) and names containing underscores;
  - use `SparseFields` as an additional authoritative source for sparse labels;
  - preserve first-seen order and reject ambiguous legacy encodings with a clear error
    instead of silently selecting the wrong application field.
- Reuse or add narrowly scoped helpers beside
  `OpenPMDUtils::GetMeshRecordAndComponentNames` so writer and reader agree on the
  record-name grammar rather than maintaining unrelated string parsing rules.
- Confirm that discovery does not require loading record payloads and remains valid
  after the iteration is explicitly opened in serial and MPI configurations.

## Phase 4: Complete the analysis data path

- Exercise the existing `VariableExists`, `ReadBlocks`, `GetSparseInfo`, and
  `BlockdataIsPadded` paths with the discovered analysis descriptor and correct any
  assumptions that only hold for full restarts.
- Preserve openPMD's native unpadded/interior layout: use the existing chunk-offset and
  extent calculation for each block, level, topological element, and component, then
  rely on the analysis initialization path to populate destination ghost zones.
- Verify that filtered-out fields are neither allocated nor read, while selected dense
  and sparse fields retain their shapes, component ordering, allocation masks, and
  deallocation counts.
- Keep normal `-r` behavior unchanged, including package-parameter restoration, swarm
  loading, format-version handling, and mixed HDF5/openPMD restart sequences.

## Phase 5: Regression and unit coverage

- Extend the analysis-data regression with an openPMD producer/output variant and run
  the second step with `-a` on the generated `.bp` dump.
- Reuse the HDF5 analysis assertions to verify:
  - all file-backed registered fields are discovered when no filter is supplied;
  - an explicit field filter selects only its intersection with the dump;
  - dense, derived, vector/component, and sparse-ID labels map to one logical field;
  - excluded or omitted fields are not allocated or written by the analysis run;
  - interiors survive the load and same-level, physical, and coarse/fine ghosts are
    valid after analysis initialization;
  - time, cycle, input overrides, and analysis-only fields behave identically for HDF5
    and openPMD sources.
- Add focused reader tests for the new attribute, filtering, duplicate record removal,
  names containing underscores, multiple AMR levels/topological elements, and the
  legacy fallback. Include a negative test for a legacy name that cannot be decoded
  unambiguously.
- Retain the existing `restart_opmd` regression as the non-analysis compatibility gate.

## Validation

- Run `git diff --check` and the repository formatter on touched C++ files.
- Build with both HDF5 and openPMD enabled.
- Run focused reader/unit tests, the HDF5 and openPMD analysis-data regressions, and the
  existing `restart_opmd` regression in serial.
- Run the openPMD analysis and restart regressions with the configured MPI test size to
  verify collective iteration opening, metadata visibility, and block-local chunk
  reads.
- If supported by CI, also build with only one output backend enabled to ensure the
  shared `RestartReader` interface and conditional compilation remain correct.

## Scope Boundaries

- Do not redesign the analysis state-selection or boundary-fill algorithms; this work
  supplies openPMD with the same field-discovery and loading contract already used by
  HDF5.
- Do not change the openPMD mesh data layout, naming format, or restart semantics solely
  for analysis loading.
- Swarm discovery for analysis is outside this parity step unless the common analysis
  path begins selecting file-backed swarms; existing swarm restart support must remain
  intact.
